# MultiVPN Android

نسخه اندرویدی MultiVPN — **فاز ۳ (برابری قابلیت با نسخه ویندوز)**. با Kotlin +
Jetpack Compose و همان هویت بصری نسخه ویندوز (پالت aurora: #070912 + ایندیگو
#6D5DFB → فیروزهای #2DD4E8).

> **وضعیت صداقت (همان قرارداد نسخه ویندوز):** «وصل شد» فقط زمانی گفته میشود که یک
> پاسخ **۲۰۴ واقعی از داخل تونل** گرفته شده باشد. عدد پینگ هم یک **اندازه‌گیری
> واقعی end-to-end** است (درخواست HTTP از داخل خود پروکسی)، نه زمان اتصال TCP؛
> کانفیگی که جواب نداد «تایم‌اوت» میگیرد و عدد قبلیش هم از کش پاک میشود.

## چیزی که الان کار میکند

**تونل:**

- **اتصال واقعی** — Hysteria2 / VLESS (+Reality) / Trojan / Shadowsocks از لینک،
  و **WireGuard / AmneziaWG** از فایل `.conf` (پارامترهای مبهم‌سازی
  Jc/Jmin/Jmax/S1..S4/H1..H4/I1..I5 دقیقاً همان‌طور که سرور فرستاده عبور میکنند —
  رنج `min-max` هرگز کوتاه نمیشود چون handshake را بی‌صدا میشکند).
- **هسته:** `hiddify-core-4.1.0.aar` — همان هستهای که نسخه ویندوز استفاده میکند؛
  داخلش sing-box **v1.13.0** است (`Libbox.version()` در ران‌تایم: 1.13.1).
  فایل AAR در گیت نیست (~۱۰۷MB): `./fetch-core.ps1` آن را دانلود و با SHA256
  موجود در `core-hashes.json` تأیید میکند.
- **اثبات ترافیک:** موتور بعد از start هسته، `cp.cloudflare.com/generate_204` را
  از داخل TUN صدا میزند و فقط ۲۰۴ واقعی (یا ۲۰۰ با بدنه خالی) را قبول میکند؛
  ریدایرکت/بدنه‌دار = کپتیو پورتال = وصل نیست.
- **هنوز نه:** IKEv2 و OpenVPN — موتور این نسخه sing-box است و این دو را ندارد؛
  اپ صریحاً میگوید «پیاده نشده» و کانفیگ را رندر نمیکند.

**قابلیت‌هایی که در این فاز رسیدند (همه با نسخه ویندوز برابر یا بهتر):**

- **پینگ واقعی هر کانفیگ** — با `urlTest` هستهٔ sing-box: همهٔ کانفیگ‌ها داخل یک
  گروه `selector` هستند و هسته از داخل هر کدام یک درخواست واقعی میزند. وقتی
  قطع هستید یک کانفیگ **بدون TUN** بالا میآید تا اندازه‌گیری هیچ هزینهای برای
  ترافیک شما نداشته باشد. دکمه در حین اجرا «لغو (۱۲/۵۷)» میشود.
- **سوییچ کانفیگ بدون قطع اتصال** — چون همه در یک selector اند، تغییر کانفیگ
  فقط یک `selectOutbound` روی هستهٔ زنده است؛ سشن، TUN و مسیرها دست‌نخورده
  میمانند (`interrupt_exist_connections` هم روشن است تا IP خروجی واقعاً عوض شود).
- **کارت ترافیک زنده** — دانلود/آپلود (کل و بر ثانیه)، تعداد اتصال و مدت سشن،
  از شمارش خود هسته. اگر هسته هنوز شمارشی ندارد، اپ همین را میگوید و «۰ بایت»
  جعلی نشان نمیدهد.
- **تانل تفکیکی per-app** — انتخاب اپ‌ها با نام بستهٔ اندروید (`include_package`
  یا `exclude_package`). این را خود اندروید اعمال میکند، پس **از نسخه ویندوز
  قابل‌اعتمادتر است** (آنجا به تطبیق نام پروسه وابسته است).
- **جستجو + مرتب‌سازی «سریع‌ترین»** — مرتب‌سازی لایه‌ای: عدد گرم → عدد تازه →
  کش → کش کهنه → اندازه‌گیری‌نشده → ناموفق.
- **مدیریت کانفیگ** — تغییر نام، ویرایش لینک، اشتراک‌گذاری با share sheet،
  حذف با تأیید؛ اشتراک‌ها بروزرسانی/حذف میشوند (بروزرسانی هرگز کانفیگ قدیمی را
  پاک نمیکند — یک ساب که موقع قطعی لیست کوتاه برگرداند نباید داده را ببرد).
- **پشتیبان‌گیری رمزشده** — AES-256-GCM با کلید مشتق‌شده از رمز کاربر
  (PBKDF2، ۲۱۰ هزار دور). هدر فایل با نسخهٔ ویندوز یکی است (`MVPNBAK1`)، پس
  پشتیبان بین موبایل و کامپیوتر جابه‌جا میشود.
- **لاگ اپ** — همان `app.log` نسخه ویندوز، از داخل تنظیمات قابل دیدن و پاک کردن.
- **تنظیمات واقعی** — اتصال خودکار، اتصال مجدد، جلوگیری از نشت DNS + انتخاب
  رزولور.

**مدیریت کانفیگ (از فاز ۱):**

- **ایمپورت لینک** — vless / trojan / ss / hy2، چندتایی، حتی وقتی IME یا کلیپبورد
  خطوط را به یک خط فاصلهدار تبدیل کند (split روی هر whitespace).
- **ایمپورت فایل** — ‎.conf (WireGuard/AmneziaWG با تشخیص نسخه AWG) و ‎.ovpn از طریق SAF.
- **اشتراک** — دریافت URL (http/https) و پارس base64 یا plaintext.
- **ذخیرهسازی** — JSON اتمیک (temp + rename) در `files/data`؛ فایل خراب → قرنطینه
  `.corrupt-*` (هرگز خالی نمیشود)؛ نجات trailing-comma + BOM برای subscriptions.json
  (همان فیکس 3.6.17 دسکتاپ، string-aware).
- **اسرار** — لینکها قبل از نوشتن با **Android Keystore** (AES-256-GCM) رمز میشوند؛
  معادل DPAPI نسخه ویندوز. اگر Keystore در دسترس نباشد اپ به‌جای از دست دادن داده
  بدون رمز ذخیره میکند ولی این را در لاگ **اعلام** میکند (سکوت در این مورد ممنوع).
- **هسته مشترک با دسکتاپ** — `app/src/main/java/vpn/core/` کپی بایتبهبایتِ
  `desktop/src/main/kotlin/vpn/core/` است (همان پکیج `vpn.core`):
  `Links.kt` · `Models.kt` · `Ports.kt` · `LatencyGrade.kt` · `Awg.kt`.
  `LinksParityTest` رفتار پارسر را قفل میکند تا کپیها واگرا نشوند. دو فایل
  اندروید-اختصاصی هم اضافه شده: `ConfigSort.kt` و `WgConf.kt`.

## دیباگ هستهی تونل

libbox یک کتابخانه **Go** است؛ شکستش با استک‌تریس جاوا اعلام **نمیشود**. سه ابزاری که
واقعاً جواب میدهند:

```bash
adb logcat -d | grep "MultiVPN\."      # مسیر ما: openTun/TUN established/checkConfig
adb logcat -d | grep " E Go *: "       # پنیک واقعی هسته (goroutine + فایل:خط)
adb shell run-as com.multivpn.android cat files/box/stderr.log   # redirectStderr
adb shell run-as com.multivpn.android cat files/active_box.json  # کانفیگی که هسته گرفت
adb shell ip -o addr show | grep tun   # دستگاه TUN بالا آمده؟
adb shell "cat /proc/net/dev | grep tun0"  # شمارندهی بایت = ترافیک واقعاً رد شده؟
```

`checkConfig` همیشه قبل از `startOrReloadService` صدا زده میشود تا خطای اسکیمایی
بهجای «تایم‌اوت ۲۰ ثانیهای» گزارش شود.

### چیزی که عمداً روی اندروید نیست (و چرا)

- **حالت‌های TUN / proxy-only / system-proxy:** روی اندروید `VpnService` خودش
  TUN است؛ نه API پروکسی سیستمی هست و نه راهی که پورت محلی را به اپ‌های دیگر
  بدهیم. یک سلکتور سه‌حالته اینجا فقط یک کلید بی‌اثر بود.
- **پورت پروکسی محلی:** هیچ‌چیز روی دستگاه به پورت محلی وصل نمیشود.
- **دیالوگ بستن پنجره / تری:** اندروید دکمهٔ X ندارد.
- **IKEv2 / OpenVPN:** خارج از توان هستهٔ sing-box. اپ صریح میگوید، جعل نمیکند.

### نکته معماری (چرا کپی، چرا KMP نه)

`vpn.core` دسکتاپ درهم است: فایلهای پرتابل (Links/Models/…) کنار فایلهای Windows-only
(HiddenRun/JNA، Proxy/رجیستری، OpenVpnBin/…). تا وقتی KMPسازی انجام نشود، پنج فایل پرتابل
با پکیج یکسان کپی میشوند و تست پاریت واگرایی را میگیرد. تغییر در هر سمت = سمت دیگر هم.

### قراردادها (ارثبریشده از PLAN.md دسکتاپ — خلاصه)

- هیچ عدد/وضعیت جعلی: «وصل» فقط با ترافیک تأییدشده؛ «Skipped» یعنی هیچ pill.
- منطق تصمیم = تابع خالص + تست (نه لامبدای Compose).
- قبل از تنظیم هر ثابت زمانی/آستانه، اندازه بگیر (درس دور ۸ دسکتاپ).

### پنج تلهی فاز ۲ (هر کدام یک بار کل تونل را کشت)

اگر تونل «شروع میشود ولی کار نمیکند»، اول این پنج مورد را چک کنید — همه در
`BoxConfigSchemaTest` یا کامنت کد قفل شدهاند:

1. `FOREGROUND_SERVICE_SPECIAL_USE` در manifest نباشد → از API 34 `startForeground`
   استثنا میدهد و سرویس در `onCreate` میمیرد، قبل از صدا زدن libbox.
2. `Libbox.setup()` در `Application.onCreate` صدا زده نشود → هر تماس بعدی داخل Go
   شکست میخورد بدون هیچ خطای جاوا.
3. `CommandServer.start()` فراموش شود → `startOrReloadService` بی‌اثر است.
4. `startOrReloadService(json, null)` → sing-box 1.13 همان اول `OverrideOptions` را
   dereference میکند؛ `null` یعنی SIGSEGV و مرگ کل پروسه. `OverrideOptions()` خالی بدهید.
5. اسکیمای کانفیگ ۱.۱۱ به هستهی ۱.۱۳: `inet4_address`/`inet6_address` → آرایه
   `address`؛ `sniff` از inbound → `{"action":"sniff"}`؛ outbound نوع `dns`/`block`
   حذف شده → `{"action":"hijack-dns"}` و `reject`؛ سرور DNS به شکل
   `{"type":"https","server":…}`. همچنین `getInterfaces()` نباید zone آدرس IPv6
   (`%dummy0`) را بدهد و `flags` باید بیت‌های `net.Flags` گو را داشته باشد.

### سه تلهی فاز ۳

۱. **`fd.detachFd()` در `openTun`** → libbox مالکیت دیسکریپتور را نمیگیرد، پس
   دیگر کسی آن را نمیبست: هر reconnect یک fd لیک میکرد و یک دستگاه tun
   جامانده میگذاشت (مشاهده‌شده: `tun0`/`tun1`/`tun2` بعد از سه اتصال). الان
   `fd.fd` برگردانده میشود و خود سرویس در `closeTun()` میبندد.
۲. **حافظهٔ dedupe در `DefaultNetworkMonitor`** بین دو اتصال پاک نمیشد → هستهٔ
   تازه هیچ‌وقت اینترفیس پیش‌فرضش را نمیگرفت، چون monitor فکر میکرد «eth0
   قبلاً گزارش شده». نتیجه: reconnect همیشه تایم‌اوت میشد در حالی که اتصال اول
   سالم بود. `start()` الان حافظه را صفر میکند.
۳. **۶۵۵۳۵ عددِ تأخیر نیست** → sing-box با این مقدار (بیشینهٔ uint16) شکست dial
   را اعلام میکند. بدون فیلتر، لیست «۶۵۵۳۵ ms» نشان میداد، یعنی یک عدد ساختگی
   دقیقاً از همان جنسی که این پروژه ممنوع کرده. `CoreClient.isRealDelay` قفلش
   میکند و کانفیگ ناموفق «تایم‌اوت» میگیرد و عدد کش‌شدهاش هم پاک میشود.
